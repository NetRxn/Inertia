# Use Inertia

## Find the right surface

Open the admitted member app or Paperclip installation with your own account and current organization permissions. The pilot uses Cloudflare Access plus application authentication. Never share a login link, session cookie or signing key. Enabling signup does not prove that a person has joined successfully.

The member app answers organization questions using its existing shared corpus. Paperclip shows the actual tasks, documents, sources, reviews and next actions. A citation chip identifies a source; it is not a grant eligibility decision or an immutable artifact-approval receipt.

## Work an opportunity

1. Open the Coordinator's funding case queue. Use sponsor, official URL, current deadline or explicit unknown, organization fit, evidence, effort and remaining human facts to understand priority. An active shortlist can be useful before an exhaustive source scan is complete.
2. Open the corresponding Beta case. Preserve its binding and current saved work. A task title is only a label; sponsor identity comes from the bound official source. INE-66 is FC Dallas, while Communities Foundation of Texas is a different case.
3. Read the latest saved draft/document. Proposed activities, cost assumptions and commitments must remain distinguishable from verified organizational facts. Review the current revision rather than combining contradictory older fields into a new document yourself.
4. Inspect Charlie's exact review and the producer's response. A rejected source should return actionable corrections to the same case. Source acceptance settles that source version; draft/candidate/gap/whole-packet review has its own contract.
5. Read or download the current human-readable artifact when available. Markdown is an acceptable MVP draft. A render, attachment or successful agent run does not itself establish a coherent approved application.
6. Resolve only the genuine final human decisions: authorized contact/legal records, adopted scope/amount, actual finances/partner commitments, permissions and submission authority. Ordinary public research and proposed drafting remain agent work.

## Read status accurately

- **In progress:** execution is active; useful output must still be inspected.
- **Blocked / review pending:** inspect the specific dependency or review. It does not mean the whole portfolio must stop.
- **Source accepted:** the exact source proposal passed its independent review. It does not mean the application was approved.
- **Draft saved/rendered:** work exists and can be read; check substance, current revision and unresolved decisions.
- **Task done:** native lifecycle outcome, not proof of funder submission or award.

## If something is unclear

Look for the current document revision, exact review scope and named next action. Ask the operator about unavailable access or an uncertain deployment. Do not retry a timed-out mutation blindly, clear holds, invent missing facts or send an application from the demo. Current submission remains manual; future agent submission needs separately qualified exact-package authorization.
