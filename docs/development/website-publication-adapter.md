# Inertia website publication adapter

Implemented caller-side module: [website.ts](../../src/roundtable/website.ts). Contract: [v1 proposal](../integrations/dao-website-member-publication-proposal.md) and explicit [v1.1 clarifications](../integrations/dao-website-publication-v1.1-clarifications.md).

Status: caller contract-tested. Website routes, authorized source adapter and native job wiring are pending. Existing demos use `pendingDaoPublisher`.

## Caller-owned persistence and scheduling

The adapter deliberately does not implement the old `Publisher` interface. Its generic core `publish` catches transport errors and can only report pending/conflict; that would hide actionable auth, rate-limit and withdrawal outcomes. The website-specific call takes the already prepared core output and supplies the richer outcome below, while sharing the unchanged digest codec. Existing callers stay compatible.

1. Trusted source adapter calls core `prepare` and supplies explicit meeting metadata, fixed HTTPS origin and stable scoped principal ID. Originals stay in the authorized source system; preparation verifies their hash/normalization before discarding `raw` from the HTTP body.
2. Call `prepareWebsiteOperation(prepared, meeting, binding, previousRecord?)`. For a correction supply the saved previous record and its matching output hash as the core CAS parent. Same meeting/target/principal required. No automatic rebasing. Metadata-only correction throws `WebsitePreparationError` with code `metadata_only_correction_unsupported`.
3. Persist the **entire returned record before any network call** in private, company/target/principal-scoped native plugin state. It contains sensitive member transcript/metadata but no token or extra raw-original copy. Use a single native owner/checkout for each meeting and a stable per-operation state key; load an existing record rather than overwriting it with newly generated bytes. Use existing native state and scheduling. Existing [RuntimeState get/set](../../src/bridge/runtime.ts) is a usable storage port under that native ownership; it is not an atomic first-writer API, and concurrent uncoordinated get/set is NOT safe operation binding.
4. Create `createWebsitePublisher({ origin, principalId, token, fetch })` from separately authorized scoped configuration. The token never enters the persisted operation. It is snapshotted per client; do not switch principal/collection while retrying an operation. A principal ID represents a fixed authorized resource scope, not an arbitrary display label. Origin must be a bare HTTPS origin without trailing slash, path, credentials, query or fragment.
5. Call `client.publish(savedRecord)`. It validates a cloned record before I/O, GETs the immutable operation, writes only after explicit authorized `404 operation_absent`, then GETs again. POST headers enforce first-write/CAS preconditions, and every retry sends the same saved UTF-8 body string. Redirects are refused, requests use 15-second abort signals and no-store caching, and response bytes are bounded. There are no inline POST retries.
6. Persist the outcome and retry-not-before/pause state in the existing native job/runtime state before another scheduled execution. Client memory suppresses repeated calls after 401/403 or until a 429 not-before time; durable suppression across process restarts is the caller's job. The caller must recheck enabled configuration and authorization before dispatch. Do not resume auth-blocked jobs automatically on a timer. Explicit reconfiguration/admission resumes them.

The exact-body record is JSON-safe. Native JSONB can reorder record keys without changing the `body` string, so reconstruction/restart does not require recomputation. The receipt's body hash is verified against that string. Do not store records in Buzz, public CI logs or issue bodies. Apply the selected records retention policy to local state too; withdrawal must persist a stopped outcome so a job cannot recreate content.

## Outcomes and operator behavior

| Outcome | Meaning | Native caller next step |
|---|---|---|
| `published` | POST followed by full verified GET | Save receipt; finish quietly. |
| `already-published` | Existing immutable receipt verified | Save receipt; finish quietly, even if current=false. Never roll the pointer backward. |
| `pending` | Receipt not authoritative or write not confirmed | Keep record; retry through the same read-first call on normal reconciliation cadence. Do not claim success. |
| `deferred` / `rate_limited` | 429; retryAt is epoch milliseconds | Persist retryAt; do not dispatch before it. Numeric/date Retry-After is honored with up to one second of jitter. |
| `blocked` / `authentication_required`, `scope_denied` | Identity lost admission | Pause integration, show one content-free setup exception. |
| `blocked` / `withdrawn` | Durable operation tombstone | Stop this operation; never republish it as new. |
| `blocked` / `invalid_operation`, `body_too_large`, etc. | Local record or request is invalid | Resolve the named input/contract problem; never truncate content or change bytes under the same key. |
| `conflict` | 409/412 or mismatched full receipt | Stop automatic writes and expose one content-free native exception. Resolve against current website version before preparing a newly authorized correction. |

409/412 triggers same-operation receipt reread but never another POST or automatic rebase. The present proposal has no general current-meeting lookup route; resolving a conflict against the current version is a separate website/native workflow, not a guessed endpoint. The caller retains the previous record for correction context. Auth/withdrawal/deferred outcomes during that reread take precedence.

No response/error text, transcript, token, model attribution or external redirect is surfaced by the adapter's outcome codes. Verified success receipts themselves contain member content and must remain in protected state, not be logged wholesale. `readbackPath` is a machine-only relative receipt route, not a public share link.
