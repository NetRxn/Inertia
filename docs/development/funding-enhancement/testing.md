# Funding enhancement acceptance

This is the test specification for spec.md and plan.md. No new implementation test has been run by this design task.

## Evaluation tracks

| Track | Inputs | What the result measures |
|---|---|---|
| synthetic_contract | Minimal explicit fixtures | Deterministic semantics, scope, replay and failure handling |
| public_current | Frozen current public evidence and current notices for the five named cases | Present-day useful drafting and research behavior |
| historical_exact | Exact July input/output artifacts, code revision and as-of date | Paired improvement against the retained July baseline |

Historical artifacts are not presently in the cloud workspace. Their absence does not delay public-current implementation. Preserve closed-cycle labels and next-cycle/partner routes; the five cases are regression subjects, not a claim that all are currently actionable grants. Capture sources with retrieval timestamp, original publication date where known, content hash and permitted audience. Do not include later evidence in historical replay.

## Quality rubric

For each requirement, a reviewer scores usefulness: 0 missing/ceremonial, 1 useful partial, 2 substantive draft within available evidence. Report both the field-level scores and eligible-field denominator. Do not award points for filling genuinely unknown financial/legal/commitment fields with guesses. A proposed plan can score 2 as a proposal, never as historical fact.

### Reproducible scoring protocol

Before running a candidate, freeze each requirement's ID/version, route/owner, required answer components, source-span evidence, prohibited claims and expected genuine gaps. An independent reviewer admits this gold fixture, including answerable/not-answerable/partially-answerable classification with reasons. The denominator comes from all sponsor requirements, not emitted answers or producer gap labels. Omitted answers and unsupported-field hiding score zero; show lead-owned and genuinely unknown fields separately without deleting them from coverage.

1. **Hard checks:** deterministic validators check required fields, route/deadline disposition, evidence membership/version/hash, exact claim spans, numeric formulas/units, forbidden mutations, scope and historical cutoff. Store check ID, expected value, actual value and failure. Any material hard failure blocks qualification regardless of average score.
2. **Semantic rubric:** independent reviewers see the frozen requirement, exact answer and cited passages. Score 0 if absent, merely procedural/hedged, or materially unsupported; 1 if at least one required substantive component is supported but another answerable component is missing; 2 if all answerable components are substantively drafted, with only gold genuine gaps remaining. For each factual claim record supported/partial/unsupported/contradicted and supporting excerpt; proposed outcomes must be future-tense and cannot imply authorized resources.
3. **Human burden:** classify each explicit human request against gold evidence and authority boundaries. Avoidable means a cited available source already answers it or a prescribed permitted research step was skipped. Genuine decisions or unavailable private information are not avoidable. Record the request, classification and reason, not only a count.
4. **Adjudication:** two reviewers independently score all five cases using a versioned rubric. Store identities/model versions, inputs, scores and rationales; disagreements go to a separate adjudicator, with original votes retained. A designated human audits unresolved disagreements and every material unsupported claim before accepting a release comparison. A model's self-assessment is never the final acceptance record.

Persist per-case JSON with fixture/rubric/candidate/evidence hashes, deterministic results, independent assessments and adjudication. Re-running the arithmetic over these frozen records must reproduce reported metrics. Model assessment may vary; report disagreements instead of claiming deterministic semantic truth. An unadjudicated case remains provisional.

Track supported factual claims / all factual claims; material unsupported claims; current requirement coverage; avoidable human requests; unresolved genuine decisions; route errors; human correction time; elapsed time; runtime/model/tool versions; token/tool cost when observable. A second reviewer independently checks all five cases and resolves scoring disagreements before comparison.

Initial qualification target (engineering choice): every demonstrably answerable field has a useful draft; every material factual assertion has claim-specific support; zero invented achievements, commitments or eligibility; zero avoidable human requests where existing current evidence directly answers the question. Report partial compliance explicitly rather than averaging a safety failure away. Quantitative comparison requires paired inputs and outputs, not the audit's placeholder count alone.

## Rehearsal

1. Ingest a public objective and current public grant evidence.
2. Produce a cited draft and concise meeting brief without privileged DAO access.
3. Independent reviewer identifies one concrete error; agent repairs it once.
4. Supply a synthetic meeting decision plus a sanitized financial fixture. Verify scoped knowledge reuse in a second opportunity.
5. Record actual authorized human review through the native UI; replay and stale-revision attempts behave correctly.
6. A second member runtime contributes within its evidence scope; attempts to read restricted material fail.
7. Show links, hashes, current state and unresolved external inputs. Record every actual runtime and integration exercised.

Use synthetic fixtures before live admission. Production source access, financial credentials, actual reviewer roles, website server rollout and on-chain authority remain separate setup gates. No laptop session is needed for the cloud rehearsal.
