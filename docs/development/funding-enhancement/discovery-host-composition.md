# Bounded discovery host composition

Default-disabled extension of the existing Inertia plugin, not another installation or scheduler. Paperclip owns assigned work, checkouts, wakeups and native documents; DFW owns captured evidence, candidate records, admission and saved knowledge; the existing Buzz outbox owns transport delivery.

## Executable path

1. The assigned scout calls `funding-discovery-context`. Native checkout, company/project, installed configuration fingerprint and pinned DFW principal mapping are checked. DFW saved knowledge is queried before research. The agent receives only configured public search facets for its existing authorized browser/search runtime.
2. `funding-discovery-submit` accepts URLs, never source rules, facts, credentials or process configuration. The trusted DFW process captures public HTTPS using bounded pre-send public-IP pinning, TLS hostname validation, no redirects, byte/time limits and source admission rules. Existing candidate/partner-research writeback is reused. Unresolved leads and budget charges persist before I/O.
3. Qualified known-source captures can produce an evidence-backed preliminary brief and urgent date alert without a signoff-ready packet. Eligibility and fit remain unknown unless separately established; official date-only deadlines do not invent a cutoff. Canonical packet rendering remains downstream.
4. Assigned independent diligence receives native work and uses `funding-diligence-context` / `funding-diligence-submit` for exact official program-name admission, with a distinct principal, checkout, query receipt and current source hash. An optional quarantined new origin instead uses `funding-source-validation-submit`: a separately qualified official captured page must link to the exact quarantined URL with exact sponsor-name text. The result admits identity for that capture only, never funding facts, eligibility or a recurring adapter.
5. Urgent triage documents and agent wakeups are separate from human transport. Optional admitted Buzz delivery uses the existing signed outbox with immutable material-event identity, exact audience binding, current-source checks, guarded claims and transport acceptance receipts. Acceptance is not proof of reading. Base bridge reconciliation does not consume alert records.
6. The unscheduled `funding-discovery-recheck` native job rechecks due work and requests native follow-up. No new recurring job is activated. A failed/empty wakeup is not counted as execution. Existing per-objective owner prevents overlap; no lease stealing.

## Native SDK constraint

The pinned SDK cannot pass `baseRevisionId` to update an issue document. Discovery therefore writes immutable native snapshots with a deterministic logical-key prefix and monotonic sequence under the existing owner. Reads explicitly sort sequence, independent of native list ordering. Identical latest content is reused, including after lost-create acknowledgment. This is native work evidence/frontier, not a second task ledger. Older snapshots are history, not current instructions. Requalify replacement with native revisions when the SDK supports them. Recurring production use must qualify long-lived document inventory/read costs; this bounded disabled slice does not claim unlimited history scalability.

## Qualification boundaries and activation inputs

Tests distinguish injected HTTP/capture fixtures from actual native Paperclip services, PostgreSQL persistence and the cold pinned Python DFW subprocess. No live search/model quality, real sponsor discovery, recipient delivery or recurring scheduling is claimed from mocks. Activation needs admitted native scout/reviewer identities and issue scopes, plus a host-resolvable active responsible member on scout/diligence/urgent work issues under the native wake policy (`responsible_user_unresolved` is an activation blocker, not scheduled work), existing authorized research/browser tools, deployed DFW process/tenant pins and source-review policy, explicit public query facets/budgets, and an acknowledged human Buzz destination/purpose. No new provider account or credential is created here.

## Source-bound new-sponsor funding facts

Merged in Inertia PR36 and DFW PR52. After exact-capture identity corroboration, `funding-facts-submit` uses the assigned independent reviewer, current query/capture/hash/identity receipt and exact normalized-source spans for program name, deadline and benefit. The trusted DFW service revalidates both capture chains, scope and stored claim units, interprets supported complete deadline/benefit statements conservatively and records a durable source-bound assessment. No site-specific recurring adapter is required.

Conditional preliminary briefs preserve unsupported cutoff/timezone, eligibility and fit as unknown. Total pools and in-kind statements do not become per-award amounts. Reviewer budgets, current-source replay, supersession and material-event deduplication persist through reconstruction; the existing native snapshots and signed Buzz delivery remain the output path. Actual native/cold-process qualification used controlled captured HTML and agent calls. Live search/model quality, real relay/human reading and recurring activation remain separate qualification work.

Tests cover exact captured date and benefit; invented/mismatched quote rejection; stale/revoked primary or corroborating capture; same actor and wrong scope; ambiguous or partial claims; expired cycles; persisted reviewer budgets; restart/replay; and changed-deadline supersession. Missing or unsupported facts remain agent-owned evidence work.
