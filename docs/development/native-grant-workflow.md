# Native and Buzz application review contract

The chosen v2 member policy below supersedes the earlier named-owner/default specialist-human review design for new work. It is in progress, not merged or deployed. Existing source remains the legacy v1 path plus source-qualified default-disabled host assembly in [PR53](https://github.com/NetRxn/Inertia/pull/53). Preserve v1 approvals, immutable packets, receipts, cancellation state and historical meaning without reinterpretation.

## Current member target

Any authenticated, currently verified DAO member with current application action access can contribute and approve the exact version. No named human application owner or default five-specialist gates. Agents do preparation and independent quality review, never human approval. Public visibility, a repository/native role, Buzz pairing or forwarded actor flag alone establishes neither current DAO membership nor application action access.

Trusted action handling resolves current identity/membership/application rights for contribution, exact packet confirmation, recording submission and attaching evidence. It fails closed when the authoritative current-access adapter is unavailable. Reuse existing native/Buzz identity and application ACL facilities rather than inventing another permission system. Native denial remains authoritative.

A v2 confirmation binds an explicit policy/version, immutable packet/version/hash, exact artifact bytes and real human action. Source/readiness checks apply to approval. Corrections create new versions needing their own confirmation. One member action cannot generate fabricated specialist approvals. Actual sponsor signatures/certifications and DAO/Vocdoni decisions apply when required by the selected case, not as universal ceremony.

## Mark submitted records an external fact

One Mark submitted action or equivalent authenticated Buzz intent records the selected immutable packet and actual date. Preserve reporter separately from a claimed actual submitter, actual review/readiness state and evidence level. A preserved historical packet may be selected deliberately; changed selection cannot retarget silently. Missing earlier approvals remain missing instead of being invented or made a prerequisite to recording what happened.

Receipt image/email/reference is optional and can follow later. Member attestation and attached evidence do not automatically become provider-verified. Corrections and evidence append audited history linked to the same selected packet; original meaningful reviewed/final/submitted records remain retained. Exact action/content replay returns the same result; changed content conflicts. Group text/minutes are context until an authenticated member action records state.

This action does not submit to a funder, pay, create a vote or grant credentials. External submission remains a separately authorized human/service action. V2 native/Buzz action and current access wiring must be qualified before a live claim; it is not implemented by describing this policy.

## Shared preparation and knowledge

Paperclip owns native tasks/documents/budgets; Buzz shows the same work. Reuse existing funding evidence/candidate/packet services and authorized PostgreSQL domain tools. The existing authorized Buzz agent is the achievable Wednesday contribution path. It does not qualify draft PR51 or full untrusted member runtime isolation/native authoritative completion. Helix and Y2 are deferred from Wednesday.

Keep candidates, accepted applicant facts, exact-version member confirmation, actual governance and submitted attestation distinct. Preparation must be substantial system-generated work, not a manually polished reference packet substituted by dot. Private source documents and credentials stay in their authorized stores and out of public artifacts.

## Legacy v1 remains isolated

Existing v1 source includes named/specialist-role binding and direct-application freeze assumptions. Those are implementation facts, not evidence that every application genuinely requires that ceremony. Its [source-pinned primitives](../reference/native-grant-workflow.md) and [legacy composition](../implementation/native-funding-review-composition.md) remain historical/regression contracts, not the new v2 eligibility rule.

The legacy durable path captures authority for one exact command/version atomically with the native verdict. Later native changes/disconnect do not cancel that accepted instruction. Current domain authorization/evidence/head/artifact checks still gate effects; DFW-confirmed cancellation is serialized with apply and cannot undo an applied effect. Preserve per-item actor/decision identity, replay conflicts, authoritative readback and unknown-outcome hold. No cross-database atomicity is claimed. Do not migrate those records into v2 approval without an explicit qualified version transition.

PR53 source-qualified assembly, early SDK byte/deadline bounds, manual-only invocation and native state-delete reset remain default-disabled. Source-row allocation, remaining adapter/deployment/latency compatibility, approved lifecycle/authentication/network bindings, production writer fencing and live walkthrough remain gates. The published PR52 fixture is controlled evidence, not deployment. Legacy accepted receipts remain protected through terminal acknowledgement or qualified durable transfer.

## Retention and acceptance

Retention defaults are settled planning choices: 90 days for recordings after validated transcript/minutes, expendable drafts and operational logs; one year for security logs. Meaningful reviewed/final/submitted, authoritative evidence and decisions remain retained under applicable archive/grant schedules and holds. Storage binding/record owner/readable archive and grant-specific schedules remain operational inputs. No deletion is enabled.

[T-G06–15](../../testing.md#native-grant-review-acceptance-default-disabled) tests current-member exact-version actions, agent/public-only/unauthorized denial, stale/corrupt artifacts, optional/later evidence, honest missing approvals, replay/corrections, conditional real governance and v1 isolation. Actual system/runtime/source and human walkthrough evidence is still required; source qualification does not establish deployed v2.
