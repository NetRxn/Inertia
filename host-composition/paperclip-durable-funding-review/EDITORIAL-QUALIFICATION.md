# Independent application-draft review

This additive overlay admits only the configured independent Charlie to a typed `draft_review` child under the actual Beta case. Beta creates or recovers that child using the trusted `native_draft_document` descriptor returned by render. The descriptor names the complete clean native document, immutable revision and raw UTF-8 body hash. Normal numbered native documents retain all historical bytes; same-body revision changes reuse the review identity.

The reviewer receives `read_draft`, `record_draft_review`, and the existing authorized own/ancestor `list_documents` / `read_document` tools. Fresh verdicts require complete draft-page coverage. Outcomes are `changes_requested` or `no_changes_required`; both are editorial-only. Neither is source acceptance, eligibility certification, applicant-fact acceptance, final packet approval, submission authority or permission to clear a genuine hold.

The recorded result includes original producer/reviewer runs and principals, exact body identity, feedback document references and whether that body was still current at record time. A historical critique can finish after a new draft appears, but cannot approve or overwrite the newer body. A cold reviewer run can recover the same durable receipt after fresh scope and grants are validated.

Feedback documents, the editorial activity receipt and existing semantic mutation receipt commit together. The existing status-decision outbox delivers the exact child completion. Unrelated structural siblings do not consume it; human, approval, recovery, execution and explicit dependency holds remain effective. A currently running producer receives a distinct durable followup rather than silently coalescing feedback into the current turn.

No database schema, new queue, scheduler, credential, provider, permission-grant or protected configuration change is required. Install the matching four-file plugin publication slice over the current P0 package; do not replace its worker, manifest, migration or UI files with an earlier package.

Source qualification uses the disposable actual SDK worker, native PostgreSQL services, strict native input parser, driver tool declaration, durable journal and full startup. The domain render response in that SDK fixture is synthetic known bytes; the actual domain renderer has separate prior installed-image proof. Live acceptance still requires a real independent critique and version-linked Beta correction.

Installed-image qualification sets `EDITORIAL_INSTALLED_IMAGE=1`, mounts source tests and the sealed pins only, and uses the image's actual native/plugin paths. Do not mount candidate runtime replacements. Do not combine the main and historical-bootstrap files in parallel: both old fixtures use `/tmp/case-native-sql`.
